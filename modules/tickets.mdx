## The three levels

<Steps>
  <Step title="Panel">
    A message you post in a public channel, showing either buttons or a dropdown. This is the entry point members interact with.
  </Step>
  <Step title="Category">
    One option inside a panel — one button, or one dropdown entry. Each category decides where its tickets are created, who can open them, which roles can act on them, and what they say.
  </Step>
  <Step title="Ticket">
    The private channel a member ends up in after picking a category.
  </Step>
</Steps>

You can have several panels — for example, one for general support and one for report submissions — each with its own set of categories.

## Configuration

Open `/config` in your server and select **Tickets**. Every screen applies your changes the moment you make them — there's no separate save button, except when deleting a panel or a category, which always asks you to confirm first.

### The main screen

This is the root of the module: the list of your panels, with a button to add a new one. Selecting an existing panel opens its screen (below).

<Steps>
  <Step title="Open the configuration panel">
    Type `/config` in your server and select **Tickets**.
  </Step>
  <Step title="Create a panel">
    Give it a name (for your own reference — members never see it), and its message posts as soon as you've filled in a channel.
  </Step>
</Steps>

### Configuring a panel

Each panel has its own screen with the following settings:

| Setting | What it controls |
| --- | --- |
| Channel | Where the panel message is posted. Changing it moves the existing message. |
| Title | The heading members see. Pre-filled with sensible wording you can edit freely. |
| Description | The text members see under the title, explaining what the panel is for. |
| Accent colour | The colour of the panel's card. |
| Style | **Buttons** (up to 15 categories, laid out in rows) or a **dropdown menu** (up to 25 categories) — see below. |
| Placeholder | The text shown in the dropdown before a member picks anything (dropdown style only). |
| Enabled | Pausing a panel takes its message down without deleting your configuration — turn it back on to repost it exactly as it was. |
| Categories | The list of categories on this panel, with buttons to add, edit, reorder, or remove one. |

<Tip>
  Choose **buttons** for a handful of clearly-labelled options members recognize at a glance (`General support`, `Report a member`…). Choose a **dropdown** once you have many categories, or when you'd rather show a short description under each option — buttons have no room for one, a dropdown does.
</Tip>

The panel posts (or updates in place) the moment you save any of the fields above — there's no separate publish step.

### Configuring a category

Opened from a panel's category list, this screen is organized into a few groups:

**Identity**

| Field | What it controls |
| --- | --- |
| Name | The button label, or the dropdown option's title |
| Emoji | Optional, shown next to the name |
| Description | Shown under the option in a dropdown panel (not used for buttons) |
| Button style | Primary, secondary, success, or danger colour (buttons only) |
| Enabled | A paused category disappears from the panel without losing its configuration |

**Where and who**

| Field | What it controls |
| --- | --- |
| Destination | The Discord category new ticket channels are created under. Required — a category with none configured never appears on the panel. |
| Allowed roles | Who may open a ticket here. Empty means everyone. |
| Denied roles | Explicitly barred from opening one, even over an allow or over being a server admin. |
| Staff roles & permissions | Which roles can see and act on this category's tickets, and with which of the ten permissions — see [Permissions](#permissions). |
| Ping roles | Roles mentioned the moment a ticket opens |
| Ping staff roles | When on, every role holding **View** on this category is also pinged, in addition to the roles above |

**Messages**

| Field | What it controls |
| --- | --- |
| Opening message | The whole pinned message posted when the ticket is created — title, body, everything. Pre-filled with sensible default wording. |
| Closing message | Sent to the member in their closing DM — or shown on the closing card instead, if you [keep channels after closing](#closing). |

Both accept the placeholders `{user}`, `{username}`, `{display_name}`, `{server}`, `{category}`, `{number}`, and `{ticket}`. A line containing only `---` renders as a visual divider.

**Behavior**

| Field | What it controls |
| --- | --- |
| Buttons | Which controls appear on the ticket message: Close, Claim, Escalate, Staff thread, Participants, Request closure. Leaving all of them off is a valid choice — staff can still use the equivalent `/ticket` commands. |
| Claim enabled | Turns the [claim system](#claiming) on or off for this category |
| Claim lock | See [Claiming](#claiming) |
| Channel name format | How ticket channels are named. Supports `{number}` (zero-padded), `{username}`, `{display_name}`, and `{category}`. |
| Max open tickets per member | How many tickets the same member may have open at once in this category |

<Note>
  A category that has no destination configured, or that you've paused, simply won't appear on the panel. If every category on a panel becomes unusable this way, Moddy takes the panel down rather than leaving members a dead-end button.
</Note>

## Permissions

Access to a category's tickets is granted **per role**, with ten independent permissions:

| Permission | Lets a role... |
| --- | --- |
| View | See and reply inside tickets of this category |
| Close | Close and reopen a ticket |
| Claim | Take a ticket in charge, and release their own |
| Unclaim others | Take a ticket away from whoever currently holds it |
| Staff thread | Open and join the private staff-only thread attached to a ticket |
| Rename | Rename the ticket channel |
| Move | Move a ticket to a different category |
| Participants | Add or remove members and roles from a ticket |
| Stats | Read the reviews and ticket volume of this category with [`/ticket stats`](#reviews-and-ticket-stats) |
| Admin | Everything above, and keeps access even if the ticket is escalated |

<Tip>
  Claim and unclaim-others are deliberately split. Releasing a ticket you're handling yourself is routine; taking one away from a teammate is a bigger decision your team may want to reserve for leads or managers.
</Tip>

A member who opens a ticket — or anyone added to it by hand — can always see and speak in it, even without holding any role permission for that category. Whether they can also close it themselves is up to you: grant your members' role the **Close** permission if you want them to be able to.

### Who can open a ticket

Each category can restrict who's allowed to open it: leave the allow list empty for "anyone", fill it in to restrict it to certain roles, or add roles to a deny list to explicitly bar them — a deny always wins, even over an allow or over being a server admin.

## Managing a ticket

Every action below is available both as a button on the ticket itself and as a `/ticket` command — use whichever is faster in the moment.

### Claiming

If a category has claiming enabled, any agent with the **Claim** permission can mark themselves as handling a ticket:

```discord
/ticket claim
/ticket unclaim
```

The channel name picks up a small coloured dot so your whole team can tell a ticket's state at a glance:

| Dot | Meaning |
| --- | --- |
| 🔴 | Open, unclaimed |
| 🟢 | Claimed |
| 🟣 | Escalated |
| ⚫ | Closed |

<Tip>
  Enable **claim lock** on a category if you want a claimed ticket to go quiet for everyone except the claimer, your admins, and the member themselves — the rest of your team keeps read access, but only the person handling it can reply. Useful for teams where crossed wires (two agents answering the same message) are a real problem.
</Tip>

### Escalating

Escalate a ticket to hand it to your most senior staff — only roles with the **Admin** permission remain in the loop once it's escalated. If the ticket had participants added by hand, you're asked what should happen to them: keep them as they were, keep them but make the ticket read-only for them, or remove them entirely.

```discord
/ticket escalate
/ticket deescalate
```

Escalating automatically releases whoever had the ticket claimed — it's parked and handed back to them automatically if the escalation is later cancelled.

### Closing

```discord
/ticket close
```

By default, closing a ticket **deletes its channel**. In order, Moddy:

1. archives the conversation, if [transcripts](#transcripts) are on — a short _Archiving in progress_ card appears in the channel while it does;
2. sends the member who opened the ticket a DM, with your closing message and the transcript link;
3. posts the record in your [ticket log](#the-ticket-log) channel, if you set one;
4. deletes the channel.

**Prefer to keep closed tickets around?** Turn on **Keep the channel after closing** in the [module settings](#module-settings). The channel then stays, locked, behind a closing card with a **Reopen** button and a **Delete** button (the latter needs the **Admin** permission), and `/ticket reopen` becomes available:

```discord
/ticket reopen
```

Reopening gives everyone their access back exactly as it was, and tells the member by DM.

If you'd rather ask a member's permission before closing, use:

```discord
/ticket close-request
```

<Note>
  A close request points both ways. A member without the **Close** permission uses it to ask your staff to close the ticket; a staff member uses it to offer the closure to whoever opened it. Either way, the other side answers with **Close the ticket** or **Keep it open** — nobody is forced.
</Note>

### Adding people to a ticket

```discord
/ticket participants
```

Opens a form pre-filled with whoever already has access, so removing someone is as simple as unchecking them.

### The staff thread

For discussion your team needs to have _about_ a ticket without the member seeing it, open the attached private thread:

```discord
/ticket staff-thread
```

<Warning>
  Mentioning someone inside the staff thread adds them to it immediately — Discord's own behavior for private threads. Moddy automatically removes anyone who joins this way but isn't actually meant to have staff access to that category, so a stray ping can't accidentally expose the conversation.
</Warning>

### When a member leaves the server

If the member who opened a ticket leaves the server while it's still open, Moddy posts a card in the ticket saying so, with a **Close the ticket** button. Nothing closes on its own — a report may still need acting on — and only someone with the **Close** permission can use the button.

If they come back, Moddy puts them back into every open ticket they were part of, with the same access as before.

## Module settings

A few settings apply to **every** ticket on the server, whatever its category. Open `/config` → **Tickets** → **Settings**:

| Setting | What it does | Default |
| --- | --- | --- |
| Transcripts | Archive the conversation when a ticket closes | On |
| Closure detection | Offer to close when the conversation looks finished | **Off** |
| Ratings | Ask the member to rate how they were looked after | On |
| Keep the channel after closing | Keep closed tickets as locked channels, with Reopen and Delete, instead of deleting them | Off |
| Retention | Days before transcripts are deleted — `0` keeps them forever (up to 3650 days) | 0 (forever) |
| Ticket log channel | Where a card is posted every time a ticket closes | None |

Each feature can be switched off on its own.

### Transcripts

When a ticket closes, Moddy saves its whole conversation — messages, authors, attachments (as links) and Moddy's own cards. The member gets the link in their closing DM, and your staff get the same link on the [ticket log](#the-ticket-log) card.

- A very long ticket keeps its most recent 20,000 messages.
- Transcripts are kept as long as your **Retention** setting says, then deleted automatically.
- If archiving ever fails, the ticket still closes normally — the DM simply has no link.

### Reviews and ticket stats

When **Ratings** is on, the member who opened a ticket can say how they were looked after:

- a rating chosen from five words — **Poor**, **Mediocre**, **Fine**, **Very good**, **Excellent** — rather than a number;
- who helped them, pre-filled with whoever claimed (or else closed) the ticket, with a _Nobody in particular_ option;
- an optional comment.

They're offered the form right after closing their own ticket, after accepting a closure your staff offered them, and through a **Leave a review** button in their closing DM — which keeps working days later, even once the channel is gone. Each closure can be rated once, and the rating appears on the ticket log card as soon as it's left.

To see how your team is doing:

```discord
/ticket stats [staff] [days]
```

Without `staff`, you get the whole team ranked by the number of tickets handled — not by average, so one 5-star review never outranks fifty tickets — with a warning next to anyone with too few reviews for the average to mean much. With `staff`, you get that person's volume, average, rating breakdown and latest comments. `days` sets the window (30 by default, up to 365).

`/ticket stats` needs **Manage Server**, or the **Stats** permission on a category — in which case you only see the categories where you hold it.

### Closure suggestions

When **Closure detection** is on, Moddy notices when a conversation reads like it has wrapped up — _"thanks, all sorted!"_ — and posts a card offering to close the ticket, with **Mark as resolved** and **Not yet**.

- **Mark as resolved** closes the ticket if the person clicking has the **Close** permission; if they don't (typically the member), it sends your staff a close request instead. The suggestion never gives anyone a permission they don't have.
- **Not yet** keeps the ticket open, and Moddy won't suggest it again for a while.

It's off by default because it uses Moddy's AI to read the conversation.

### The ticket log

Pick a **ticket log channel** in the settings and Moddy posts one card there every time a ticket closes: its number and category, who opened, claimed and closed it, the reason, how long it lasted, how many participants it had, the transcript link — and the member's review as soon as they leave one.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can a member open more than one ticket at a time?">
    Only if you allow it — each category has its own limit on how many open tickets the same member can have simultaneously (one, by default).
  </Accordion>

  <Accordion title="What happens if I delete a panel or a category?">
    The panel message is taken down immediately. Existing tickets already opened from it are unaffected — only new ones are prevented.
  </Accordion>

  <Accordion title="Can I move a ticket to a different category after it's opened?">
    Yes, with the **Move** permission on the ticket's current category. The destination category's permissions and staff then apply going forward.
  </Accordion>
</AccordionGroup>
