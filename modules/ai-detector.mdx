AI Detector answers one question: **does this image carry a verifiable signature saying where it came from?** When it does, Moddy replies under the image with a short card. When it doesn't, Moddy says nothing.

The module is **on by default in every server**. You don't need to set anything up, and you can narrow it down or pause it whenever you like.

<Warning>
  **AI Detector is not an "AI image detector" in the usual sense.** It does not look at the pixels and it does not guess. It reads a cryptographic signature that some tools attach to their images. Most AI images carry none, and anyone can remove one in seconds. **No reply never means "this image is not AI."** Read [the limits](#the-limits) before relying on it.
</Warning>

## How It Works

### The idea: Content Credentials (C2PA)

**C2PA** (Coalition for Content Provenance and Authenticity) is an open standard for attaching a tamper-evident record of origin to a media file. Its public name is **Content Credentials**. Companies that make cameras, editing software and AI services — including Adobe, Microsoft, Google and OpenAI — are part of the coalition.

A tool that supports the standard, such as an AI image generator or a recent camera, writes a small block of data called a **manifest** inside the image file. The manifest contains:

- **Assertions** — statements about the image: the action that created it (for example "created by a generative AI model" or "captured by a camera"), the software or device, the time, and any later edits.
- **A fingerprint of the image data.** A cryptographic hash of the file's content is stored in the manifest. This is called a _hard binding_: it ties the manifest to **this exact image**.
- **A digital signature**, made with the signer's private key and backed by a certificate that identifies the organisation that signed (for example the maker of the AI tool or the camera).

If someone changes the pixels after signing, the fingerprint no longer matches and the manifest stops being valid. If someone alters the statements, the signature no longer matches. That's what **tamper-evident** means: tampering can be detected. It doesn't mean tampering is _impossible_ — see the limits below.

When a C2PA-aware editor modifies a signed image, it adds a new manifest on top of the old one. The result is a **signed history**: where the image started, then each edit, oldest first.

### What Moddy does with a picture

<Steps>
  <Step title="It picks the images to check">
    Only **PNG, JPEG and WebP** files attached to a message from a **member** (not a bot), up to 4 per message and 25 MB each. Channels you ignore, and their threads, are skipped.
  </Step>
  <Step title="It downloads the original file">
    Moddy reads the attachment as the member uploaded it, never Discord's resized preview, which would have lost the manifest.
  </Step>
  <Step title="It looks for a manifest">
    A quick scan for the C2PA marker. No marker means no signature: the check ends there and Moddy stays silent.
  </Step>
  <Step title="It verifies the signature">
    Moddy checks that the image data still matches the fingerprint in the manifest, that the signature is valid, and that the signing certificate **chains back to the official [C2PA trust list](https://github.com/c2pa-org/conformance-public/tree/main/trust-list)**. Moddy keeps that list up to date automatically (it is refreshed at least once a day).
  </Step>
  <Step title="It only keeps `Trusted` results">
    A signature that is valid but made by an organisation that isn't on the trust list, a tampered file, or a broken manifest all produce **no reply**.
  </Step>
  <Step title="It reads what the signer declared">
    Moddy walks the signed history and classifies the image from the "source type" the signer declared: created by a generative AI model, partly generated, captured by a camera, retouched, and so on.
  </Step>
  <Step title="It replies — or doesn't">
    If a result is something you chose to announce, Moddy replies under the message, without pinging anyone, in your server's language.
  </Step>
</Steps>

Reading a file sent by a stranger is done defensively: Moddy never lets the file make it contact any address, and personal data inside the manifest is never copied out (see [Privacy](#privacy)).

### A second, weaker signal: generation parameters in PNG files

Some local tools, notably **Stable Diffusion** and **ComfyUI**, write the generation settings as plain text inside the PNG. These are **not signed**. When Moddy finds them, it posts a softer card — "probably generated" — that names the tool and says this is a hint, not proof. The prompt itself is never shown.

## What the Results Mean

| Result | What it means | What it does **not** mean |
| --- | --- | --- |
| **Content generated by artificial intelligence** | A trusted signature says the image was created entirely by an AI tool. | It doesn't say _who_ asked for it, or that the picture shows something false. |
| **Content partially generated by artificial intelligence** | The signed history shows a generative AI tool modified the image. | It doesn't say _which part_ changed. |
| **Authenticated photograph** | A trusted, signed camera or phone says it captured the image, and the history shows no generative AI. | It doesn't certify that the **scene** is real: a camera can photograph a screen or a staged setup. |
| **Authenticated and retouched photograph** | Same, with ordinary retouching (crop, colour, resize…) listed on the card. | It doesn't say the retouching is harmless. |
| **Content probably generated by artificial intelligence** | An _unsigned_ PNG carries Stable Diffusion or ComfyUI parameters. | It isn't proof: anyone can add these parameters to a real image, or remove them. |

When a message holds several images, Moddy announces the most significant result.

Every card has a **More information** button. Anyone can press it to get a private panel, in their own language, with the signature details (who signed, algorithm, time, tool, camera), the signed history, how the check works, how far to trust the result, and why a missing result proves nothing. It keeps working after Moddy restarts; if the image has been deleted since, the panel says so.

## The Limits

This is the most important part of this page. Please read it before you act on what Moddy says — or doesn't say.

### 1. No result proves nothing

This is the limit that matters most. Moddy can only speak about images that **carry a trusted signature**, and most don't:

- **Many AI image tools don't sign their output at all**, especially open-source models run on someone's own computer. Others only sign some of their products.
- Even when a tool signs, the signature **doesn't survive** most of what happens to a picture afterwards (next point).

So "Moddy said nothing" means _"no verifiable information"_ — never _"not AI"_. This applies equally to authentic photos: most real photos aren't signed either.

### 2. A signature is easy to remove

A C2PA manifest is a block of data stored in the file, next to the pixels. Anything that rewrites the file without understanding C2PA drops it:

- taking a **screenshot**, or re-saving, converting, or exporting the image
- editing it in software that doesn't support Content Credentials
- messaging apps and many social networks, which **re-encode** pictures on upload

And nothing stops someone from doing this **on purpose**. A person who wants to pass off an AI image only has to take a screenshot of it, and Moddy will see an unsigned image and stay silent. C2PA is built to prove that an image is genuine _when its owner wants to show it_, not to catch people who hide it.

Whether Content Credentials survive every way of uploading a file to Discord (desktop, mobile, re-uploads) hasn't been verified for every case. Moddy reads the original attachment, which is the best Discord offers.

### 3. A signature proves what the signer _declared_, not the truth

A valid signature can't be forged without the signer's secret key. But it only tells you **what the signing tool said about itself**:

- A signed photo says "this camera captured these pixels." It doesn't say what the pixels _show_. A camera can validly sign a photograph of a screen displaying a fake image.
- A tool can sign without being specific. If the signer doesn't say whether the image is generated or captured, Moddy can't classify it and stays silent.
- A signature identifies an **organisation**, not the person who made the image.

### 4. Only signers on the official list count

Moddy trusts only certificates that chain to the official C2PA trust list. This is deliberate: anyone can create a valid signature with their own certificate, and that shouldn't count. The flip side is that:

- a **legitimate new product** whose certificate isn't on the list yet gets no reply until it is added
- Moddy refreshes the list daily, so a very recent addition or removal can take up to a day to apply
- Moddy deliberately does **not** contact any certificate revocation service while reading a file from a stranger. It relies on the trust list alone, so a certificate revoked after it was listed may still be accepted until the list is updated.

### 5. Edits that break the chain

If a signed image is modified afterwards by a tool that doesn't support C2PA, the new pixels no longer match the manifest: the signature is invalid and Moddy stays silent. Moddy never shows a "tampered" warning in a channel — only `/ai-check` explains that the signature was invalid.

### 6. "Probably AI" is a hint, not a signature

The PNG-parameters card is based on **unsigned text**. It only covers Stable Diffusion and ComfyUI PNG files, not JPEG or WebP. Someone can paste those parameters into a real image to fake it, and anyone can strip them to hide a generated one.

### 7. What Moddy deliberately does not do

- It does **not analyse the pixels** or use an "AI-or-not" classifier. Those are unreliable, and an unreliable accusation is worse than silence.
- It does **not read invisible watermarks or fingerprints** that some providers embed in their images — only the manifest stored in the file.
- It does **not check** videos, GIFs, audio, documents, links, or images shown through an embed. Only image attachments.
- It does **not sanction anyone** and it isn't connected to [AutoMod](/moderation/automod). A card is information, not a verdict on the member who posted it.

### In short

| If Moddy says… | You can conclude | You can't conclude |
| --- | --- | --- |
| "Generated by AI" (signed) | The signer declares this image was made by AI. Very reliable. | Anything about intent. |
| "Authenticated photograph" | The signer declares a camera captured it, unmodified by AI. | That the scene is real. |
| "Probably AI" | The file contains generator settings. | That it really is AI. |
| Nothing | Nothing. | That the image is real, or that it isn't AI. |

<Tip>
  Treat a card as one useful clue, not a verdict. If it matters — a contest entry, a dispute over an artwork — ask for the original file with its editing history.
</Tip>

## Privacy

Only a short list of fields is ever shown: the signing organisation, the signature algorithm and time, the generator, the camera make and model, and the names, dates and types of editing actions. **GPS position, the author's name, identity information, serial numbers and the certificate name never leave the file.** For PNG metadata, the prompt is never shown — only the generator and its technical settings.

## Configuring AI Detector

Open `/config` and select **AI Detector**.

| Setting | What it controls | Default |
| --- | --- | --- |
| **Announced results** | Which kinds of results Moddy posts: AI-generated images, AI-edited images, authenticated photos, generation metadata. Untick a kind and Moddy stays silent for it. | All four |
| **Ignored channels** | Channels (and their threads) where Moddy never answers. Up to 25. | None |

Click **Save** to apply your changes. To switch the module off entirely, press **Manage** and set it to **Paused**.

<Tip>
  If you'd rather Moddy only speak up about AI, untick **Authenticated photos** — handy in a photography server where nearly every image is signed.
</Tip>

## `/ai-check`

Not sure about an image that Moddy didn't comment on? Check it yourself.

```discord
/ai-check image:<file>
/ai-check message:<link>
```

<ParamField path="image" type="attachment">
  The image to check, as PNG, JPEG or WebP.
</ParamField>

<ParamField path="message" type="string">
  A link to a message **of this server** that contains the image. Moddy only reads it if you can see that channel and its history yourself.
</ParamField>

<ParamField path="incognito" type="boolean">
  Whether the reply is visible only to you. Defaults to your `/preferences` setting.
</ParamField>

Unlike the automatic replies, `/ai-check` **always answers**: either the result and its details, or "No verifiable information" with the reason — no signature, an untrusted or invalid one, an unsupported file. It works in servers, in DMs, and as a user-installed command.

<Note>
  If you upload the picture straight to `/ai-check`, make sure you pick the original file. A screenshot or a copy that went through a messaging app has almost certainly lost its signature.
</Note>

## Permissions Moddy Needs

Nothing beyond seeing the channel and sending messages in it.
